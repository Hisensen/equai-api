# 数字人及音乐编辑故障排查（2026-10-06）

## 数字人：根因与修复

腾讯云 API 的运行环境虽然配置了专用 r50 数字人镜像，但活动 API 容器内的 `gongji.py` 仍是旧版 `create_long_job()`：它无条件使用 `GONGJI_LONG_IMAGE`。因此数字人实际回退到普通长视频 r38 镜像。失败记录中，16:9 任务收到旧图使用的模型文件名并被当前 Comfy 模型列表拒绝；两条 9:16 任务则被旧 Worker 固定 16:9 的入参校验拒绝。

专用 r50 Worker v4 镜像已在镜像仓库和腾讯云主机的只读检查中核实：Worker 代码接受 16:9/9:16，1M 固定；模型映射是当前镜像实际提供的 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` 与 `official/minimax_h3_video_vae_int8_convrot.safetensors`。

修复已部署到活动 API 容器：`digital_human_workflow` 现在选择 `GONGJI_DIGITAL_HUMAN_IMAGE`，普通长视频仍使用原 r38 镜像；数字人不再走运行时 overlay 下载。修复后的 API 镜像为 `equai-api:digital-human-routing-fix-20261006-r1`，同一份路由源码也已放入主机部署源码，香港生产配置的数字人镜像标签同步到 v4。

生产容器内用 mock 提交路径验证了：数字人选择 v4 专用镜像，不传普通长视频 r38，也不产生 overlay 下载；API 健康检查在重启后返回 ready。普通长视频、音乐侧车、上传转发容器均保持运行。三条历史失败任务记录仍是失败状态；没有伪装成已重新出片。

## 音乐编辑：根因与修复

生产 API 当前 `H3_MUSIC_ENABLED=1`，音乐 Worker 镜像已配置，`music_available=True`；音乐侧车与上传转发容器运行正常。数据库最新两条音乐编辑记录已成功完成。截图中的“登录已失效”说明浏览器商户会话已经过期；音乐状态请求的 401 原先被页面吞掉并显示为“音乐服务暂不可用”，造成看似服务故障。

前端已部署定点修复并更新静态资源版本：401 会显示“登录已失效，请重新登录后使用音乐编辑”，其他网络/服务错误仍显示音乐服务不可用。API 与音乐 Worker 未因这项修复重启或改配置。当前状态接口未带登录态返回 401，符合鉴权预期；登录后可正常查询音乐服务状态。
